# Quadratic Equation Solver

Консольная программа на C, решающая квадратные (и линейные — как частный случай) уравнения вида `ax² + bx + c = 0`. Поддерживает интерактивный ввод, ввод через аргументы командной строки, пакетную обработку из файла и юнит-тесты.

## Возможности

- Решение квадратных уравнений с корректной обработкой вырожденных случаев: `a = 0` (переход к линейному), `c = 0`, дискриминант `= 0`, `> 0`, `< 0`.
- Три режима запуска: интерактивный, через аргументы, из файла.
- Встроенные юнит-тесты для `SolveSquare`, `SolveLine` и `IsDoubleSame`.
- Сравнение `double` через `EPS`-порог вместо `==`, отдельная функция `RemovMinusZero` для схлопывания `-0.0` в `0.0`.
- Собственные макросы отладки `DETAIL_ASSERT` / `FUNCTIONAL_ASSERT` (`my_assert.h`), отключаемые флагом `-DNMA`.

## Сборка

В проекте есть `Makefile`. Он собирает файлы из `src/*.c` (заголовки — из `inc/`) в объектники `obj/*.o` и линкует бинарник `quad`. Файлы .c/.h нужно разложить по этим двум папкам (в текущей выгрузке они лежат плоско):

```
project/
├── Makefile
├── src/    ← все .c файлы сюда
└── inc/    ← все .h файлы сюда
```

Сборка и очистка:

```bash
make        # соберёт бинарник ./quad
make clean  # удалит obj/ и quad
```

Важный нюанс: несмотря на расширение `.c`, `Makefile` компилирует всё через `g++` (`CXX := g++`), а не `gcc`. Это не опечатка — часть warning-флагов чисто C++-шные (`-Weffc++`, `-Wnon-virtual-dtor`, `-Woverloaded-virtual`, `-Wctor-dtor-privacy`, `-Wsign-promo`), и код на это опирается: например, в `unit_tests_doubleissame.c` тип `TestSuiteDoubleIsSame` используется без `struct` и без `typedef` — это валидно только в C++.

Флаги включают `-Werror=vla` (запрет VLA), `-Wconversion`, `-Wcast-qual`, `-Wstack-usage=8192` и макросы `-D_DEBUG -D_EJUDGE_CLIENT_SIDE` — похоже на сборку под ejudge-грейдер учебного курса.

## Использование

### Интерактивный режим (без аргументов)

```bash
./quad
```

Программа последовательно запросит коэффициенты `a`, `b`, `c`. Некорректный ввод (не число) сбрасывает счётчик и просит ввести заново; `EOF` (Ctrl+D) завершает программу.

### Через аргументы командной строки

```bash
./quad 1 -3 2
```

Решает `1x² - 3x + 2 = 0` и сразу печатает результат. Все три аргумента должны парситься как `double` целиком (проверяется через `strtod` + `endptr`), иначе — ошибка с подсказкой запустить `-h`.

### Из файла

```bash
./quad -f uravneniya.txt
# или
./quad --from_file uravneniya.txt
```

Формат каждой строки файла:

```
a = 1 b = -3 c = 2
```

Для каждой строки печатаются коэффициенты и корни. Если файл не найден, программа попросит ввести существующее имя файла.

### Тесты

```bash
./quad -t
# или
./quad --tests
```

Тесты читают эталонные данные из `unit_tests/TestSolveSquare.txt` и `unit_tests/TestDoubleIsSame.txt` (запускать из директории, где есть папка `unit_tests/`). Форматы строк:

```
# TestSolveSquare.txt
a: 1 b: -3 c: 2 n_r: 2 x1 = 2 x2 = 1

# TestDoubleIsSame.txt
n1 = 1.0000001 n2 = 1.0000002 ver = 1
```

где `n_r` — код количества корней (`-1` — бесконечно, `0`, `1`, `2`), `ver` — ожидаемый результат `IsDoubleSame` (0/1). В конце печатается число упавших тестов.

### Справка

```bash
./quad -h
# или
./quad --help
```

## Структура проекта

| Файл | Назначение |
|---|---|
| `main.c` | Точка входа, выбор режима запуска |
| `equation_solve.c/h` | Математическое ядро: `SolveSquare`, `SolveLine` |
| `double_operations.c/h` | Безопасное сравнение `double` (`EPS`, `IsDoubleSame`, `IsDoubleBigger`, `RemovMinusZero`) |
| `console_interface.c/h` | Разбор флагов командной строки, диспетчеризация режимов |
| `user_interface.c/h` | Интерактивный ввод коэффициентов и вывод корней |
| `unit_tests_*.c/h` | Юнит-тесты для трёх ключевых функций |
| `skipline.c/h` | Очистка stdin после некорректного ввода |
| `print_many_stars.c/h` | Декоративный разделитель вывода |
| `my_assert.h` | Кастомные ассерты, отключаемые в релизе |

## Известные ограничения

- Формат строк во входных/тестовых файлах жёстко зашит в `fscanf`; лишний пробел или другой порядок полей ломает парсинг.
- `unit_tests_solveline.c` фактически тестирует `SolveSquare` на строках с `a = 0`, а не отдельно `SolveLine`.
- Пути к тестовым файлам (`unit_tests/...`) относительные — тесты нужно запускать из правильной рабочей директории.
